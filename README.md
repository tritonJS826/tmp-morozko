# «Морозко» — демо-магазин новогодних подарков с чатом-консультантом (n8n)

Демо интернет-магазина новогодних подарков: шапка с навигацией, каталог
наборов с ценами и бейджами, блок преимуществ и контакты. Кнопка
**«Связаться с консультантом»** открывает попап с чатом, который общается
с вашим n8n-workflow через **Chat Trigger**.

## Файлы

| Файл | Описание |
| --- | --- |
| `index.html` | Витрина магазина: промо-полоса, шапка, hero, каталог из 6 наборов (инлайн-SVG), преимущества, подвал, попап чата |
| `style.css` | Новогодняя тема: снег, стекло, градиенты, анимации |
| `script.js` | Логика чата: открытие попапа, отправка в n8n, разбор ответа |
| `n8n-workflow.json` | Importable workflow: Chat Trigger → классификация → AI Agent (LLM + Memory) → ответ; передача менеджеру в Telegram и обратный канал (буфер + поллинг) |

## Быстрый старт (сайт)

Не открывайте через `file://` — браузер заблокирует CORS-запрос к n8n.
Поднимите локальный сервер:

```bash
cd webinar20261124
python3 -m http.server 8000
# затем откройте http://localhost:8000
```

Подключение к n8n задаётся вверху `script.js`:

```js
const N8N_BASE_URL   = 'https://n8n.edu.myitsupport.io';
const N8N_WEBHOOK_ID = '9cee9672-ed37-4329-8f81-f20386625bc4';
// → https://n8n.edu.myitsupport.io/webhook/9cee9672-ed37-4329-8f81-f20386625bc4/chat
```

> Важно: Chat Trigger регистрирует вебхук по пути **`{webhookId}/chat`**
> (суффикс `/chat` обязателен). Без него — 404, который браузер показывает как
> ошибку CORS. Production-URL работает только когда workflow **активен** (Active).

## n8n: workflow

Схема потока:

```
Chat Trigger → «Классификация входа» (Code)
                 └→ IF: запрошен менеджер?
                      ├─ да  → Telegram: передача менеджеру → Ответ: передаю менеджеру
                      └─ нет → IF: режим менеджера?
                                 ├─ да  → Telegram: сообщение клиента → Ответ: менеджеру отправлено
                                 └─ нет → AI Agent (OpenAI + Memory) → Ответ в чат

Обратный канал (менеджер → клиент):
Telegram Trigger → «Определить сессию» → буфер (static data)
Webhook «сообщения менеджера» → «Отдать сообщения менеджера»  ← сайт опрашивает каждые 6 сек
```

Нейронка (`AI Agent`) ведёт диалог и отвечает клиенту в чате. Как только клиент
**явно** просит менеджера («позовите менеджера», «хочу с человеком», «оператор»,
«соедините» и т.п.), нода `Классификация входа` переключает сессию в режим
`manager`: клиенту уходит «Передаю вас менеджеру», менеджер получает заявку в
Telegram, а все дальнейшие сообщения клиента пересылаются менеджеру (агент молчит).

Ответы менеджер отправляет **Reply** на сообщение бота — текст попадает в буфер по
`sessionId` (он зашит в сообщение как `[session:...]`). Сайт не может принимать push
через webhook-чат, поэтому `script.js` раз в **6 секунд** опрашивает отдельный
webhook `morozko/manager-messages` и показывает ответы в чате (стиль «Менеджер»).

Состояние сессий (`bot`/`manager`) и буфер ответов хранятся в **workflow static
data** — это нормально для одного инстанса; в queue-режиме (несколько воркеров)
нужно внешнее хранилище.

1. Импортируйте `n8n-workflow.json` (Workflows → … → Import from File).
2. **OpenAI Chat Model** — подключите credential (или замените модель).
3. **Telegram Trigger** и обе ноды **Telegram: …** намеренно `disabled`. Подключите
   Telegram-credential, укажите `chatId` менеджера в обеих нодах Telegram и включите
   их (и Telegram Trigger), когда будете готовы.
4. Активируйте workflow (**Active**) — иначе production-webhook не отвечает.
5. В **Chat Trigger → Options → Allowed Origins (CORS)** укажите домен сайта
   (по умолчанию `*` — разрешены все).

Что делает бот: здоровается и мягко узнаёт у клиента, **для кого подарок,
бюджет, пожелания, имя и контакт** (см. `systemMessage` в ноде AI Agent),
затем предлагает подходящие наборы. По явной просьбе — передаёт менеджеру.

### Передача менеджеру: как это работает

- **Клиент → менеджер.** `Классификация входа` ищет в сообщении ключевые слова
  (менеджер, человек, оператор, соедините, переключите…). При совпадении режим
  сессии меняется на `manager`, менеджеру уходит заявка, клиенту — подтверждение.
  Дальше каждое сообщение клиента уходит менеджеру в Telegram.
- **Менеджер → клиент.** Менеджер отвечает **Reply** на уведомление бота.
  Уведомления отправляются с **Force Reply** (`Reply Markup → Force Reply`), поэтому
  клиент Telegram сам открывает окно ответа — как будто менеджер нажал «Reply».
  `Telegram Trigger` → `Определить сессию` достаёт `[session:...]` из
  процитированного текста и кладёт ответ в буфер. Сайт забирает его поллингом.
- **Важно:** отвечайте именно на сообщение бота (Reply), иначе `sessionId` не
  определится и ответ не уйдёт клиенту. Строка-брендинг «sent automatically with
  n8n» отключена (`Additional Fields → Append n8n Attribution = off`).

### Если в Telegram не приходят сообщения

Ошибка **`Bad request - please check your parameters`** на ноде `Telegram: …`
означает, что Telegram отклонил запрос. Проверьте по порядку:

1. **`chatId` не плейсхолдер.** В обеих нодах `Telegram: передача менеджеру` и
   `Telegram: сообщение клиента` поле `Chat ID` должно содержать реальный
   **числовой** id менеджера (например `123456789`), а не
   `YOUR_MANAGER_TELEGRAM_CHAT_ID` и не `@username`.
   - Узнать id: напишите боту `@userinfobot` — он пришлёт ваш numeric id.
     Либо временно отключите `Telegram Trigger` в n8n и откройте
     `https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates` — в `result[0].message.chat.id`
     будет нужный id (пока Trigger включён, он «съедает» updates и `getUpdates` пуст).
2. **Менеджер нажал `/start` у бота.** Бот не может первым написать пользователю —
   Telegram вернёт `chat not found`.
   - Ошибка `403 Forbidden: the bot can't send messages to the bot` означает, что
     в `chatId` указан id **самого бота**, а не менеджера. Нужен личный numeric id
     человека (см. способ выше), а не id из `@BotFather`/`getMe`.
3. **Это тот же бот.** Credential Telegram в нодах должен быть для того же бота,
   в которого вы зашли.
4. **Обе ноды включены** (не серые `disabled`) и `chatId` заполнен в каждой.
5. Смотрите **Executions** в n8n: раскройте упавшую ноду, там будет текст ошибки
   от Telegram API — по нему сразу видно причину.

Ноды `Telegram: …` теперь помечены `onError: continueRegularOutput`, поэтому даже
при сбое отправки клиент всё равно получит ответ в чате, а не ошибку.



## Контракт webhook

Сайт шлёт POST:

```json
{
  "action": "sendMessage",
  "sessionId": "<uuid, хранится в localStorage>",
  "chatInput": "текст сообщения"
}
```

Ответ n8n — либо JSON `{ "output": "..." }`, либо SSE-стрим (если в Chat
Trigger включён «Streaming response»). `script.js` поддерживает **оба**
варианта и корректно показывает ошибки (например, 428 «credentials missing»).

## Проверка через curl

```bash
curl -i -X POST https://n8n.edu.myitsupport.io/webhook/9cee9672-ed37-4329-8f81-f20386625bc4/chat \
  -H "Origin: http://localhost:8000" \
  -H "Content-Type: application/json" \
  -d '{"action":"sendMessage","sessionId":"test-1","chatInput":"Привет!"}'
```

Успешный ответ — JSON `{ "output": "..." }` (плюс CORS-заголовки в ответе).
Если приходит `{"message":"Error in workflow"}` — смотрите **Executions** в n8n:
какая нода упала (обычно это не подключённый credential к OpenAI Chat Model).

Проверка вебхука ответов менеджера (поллинг):

```bash
curl -i "https://n8n.edu.myitsupport.io/webhook/morozko/manager-messages?sessionId=test-1" \
  -H "Origin: http://localhost:8000"
```

Ответ — JSON `{ "sessionId": "test-1", "count": 0, "messages": [] }`.
