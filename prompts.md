# Промпты для сборки «Морозко» — от лендинга до передачи менеджеру

Пять последовательных промптов для нейросети (кодинг-агента). Каждый промпт
самодостаточный: его можно копировать целиком и отдавать следующей итерации.

Проект: демо интернет-магазина новогодних подарков «Морозко» с чатом-консультантом,
который работает через **n8n** (Chat Trigger + AI Agent).

Стек и договорённости (одинаковые во всех промптах):

- Frontend: чистый HTML/CSS/JS без сборки и без фреймворков.
- Backend-логика: n8n, экспортируемый файл `n8n-workflow.json`.
- LLM: OpenAI Chat Model (`gpt-4o-mini`) + Simple Memory.
- n8n base URL: `https://n8n.edu.myitsupport.io`
- Webhook Chat Trigger: `{base}/webhook/{webhookId}/chat` (суффикс `/chat` обязателен).
- Контракт запроса сайта: `POST { action: "sendMessage", sessionId, chatInput }`.
- Ответ n8n: JSON `{ "output": "..." }` либо SSE-стрим с `data:`.
- Открывать сайт только по `http://localhost:...` (не `file://`), иначе CORS.

## Промпт 1 — Создать лендинг

```text
Ты — фронтенд-разработчик. Собери простой одностраничный лендинг интернет-магазина
новогодних подарков «Морозко» на чистом HTML + CSS + JS (без фреймворков и сборки).

Задача: сделать аккуратную, лёгкую и понятную страницу-витрину. Дизайн — новогодний,
но не перегруженный: тёмно-синий/снежный фон, один акцентный цвет (красный или
холодный бирюзовый), крупная типографика, много «воздуха». Всё должно работать
без интернета (никаких внешних шрифтов и CDN) — только системные шрифты.

Структура страницы (сверху вниз):
1. Промо-полоса: бесплатная упаковка + доставка 1–3 дня.
2. Шапка: логотип «Морозко» (подпись «новогодние подарки»), навигация
   (Каталог, Доставка, Контакты) и телефон 300-10-20 (tel:-ссылка).
3. Hero: заголовок, короткий подзаголовок про готовые наборы и помощь в выборе,
   две кнопки — «Смотреть каталог» (якорь) и «Связаться с консультантом» (id="openChat"),
   плюс 3 факта (рейтинг 4.9★, доставка 1–3 дня, 100% натуральные материалы).
4. Каталог: секция id="catalog", заголовок «Хиты сезона» и 6 карточек наборов:
   «Золотая коробка», «Мятный иней», «Фиолетовый бант», «Пряничный пряник»,
   «Полуночная звезда», «Еловый лес». В каждой карточке — картинка, название и
   описание 1–2 предложения. Бейджи: «Хит», «Новинка», «−20%».
   Иллюстрации сделай инлайн-SVG (простые подарочные коробки/ёлки/снежинки),
   чтобы не зависеть от картинок извне.
5. Блок преимуществ id="benefits": 4 пункта — доставка 1–3 дня, ручная упаковка,
   помощь в выборе, возврат 30 дней.
6. Подвал id="contacts": логотип и описание, колонки «Покупателям» и «Контакты»
   (телефон, hello@morozko-shop.com), строка копирайта с текущим годом.
7. Пустой каркас попапа чата (id="chatModal", скрыт классом hidden), кнопка
   закрытия, контейнер сообщений id="messages", форма id="chatForm" с полем
   id="chatInput" и кнопкой отправки. Логику чата пока НЕ пиши — она в следующем шаге.

Требования к коду:
- Файлы: index.html, style.css, script.js (подключи оба). В script.js сейчас только
  вывод текущего года в подвал.
- Семантическая разметка, aria-атрибуты у навигации и попапа, alt/aria-label у графики.
- Адаптивность: 1 колонка на мобильных, 2–3 на планшете/десктопе.
- Аккуратные CSS-переменные для цветов, не дублируй значения.
- Никаких console.log и мёртвого кода.

Результат: готовые index.html, style.css, script.js. Кратко опиши, что сделал,
и как запустить (python3 -m http.server 8000 → http://localhost:8000).
```

## Промпт 2 — Добавить интерактивный чат на сайт + базовый n8n-workflow

```text
Продолжаем проект «Морозко» (лендинг уже готов: index.html, style.css, script.js).
Теперь нужно:
(А) сделать попап чата интерактивным на сайте;
(Б) создать базовый n8n-workflow, который принимает сообщение и отвечает заглушкой.

=== А. Фронтенд ===
1. Кнопка «Связаться с консультантом» (id="openChat") открывает попап id="chatModal".
   Закрытие: кнопка с data-close, клик по подложке (элемент с data-close) и клавиша Escape.
   При первом открытии покажи приветствие бота — сразу, без похода в n8n.
2. Session id: генерируй один раз (crypto.randomUUID с fallback), храни в
   localStorage под ключом ny_consultant_session_id и переиспользуй для всех сообщений.
3. Отправка сообщения (submit формы id="chatForm"):
   - добавь «пузырь» пользователя в #messages;
   - покажи индикатор «печатает…» (три мигающие точки) как отдельное сообщение бота;
   - сделай POST на CHAT_WEBHOOK_URL;
   - убери индикатор и покажи ответ бота; при ошибке — заметный пузырь с понятным текстом.
   - блокируй повторную отправку, пока идёт запрос (флаг sending + disabled на кнопке).
4. Конфиг вверху script.js, отдельными константами:
   const N8N_BASE_URL = 'https://n8n.edu.myitsupport.io';
   const N8N_WEBHOOK_ID = '9cee9672-ed37-4329-8f81-f20386625bc4';
   const CHAT_WEBHOOK_URL = `${N8N_BASE_URL}/webhook/${N8N_WEBHOOK_ID}/chat`;
5. Контракт POST: тело { action: "sendMessage", sessionId, chatInput: text }.
   Разбор ответа должен поддерживать ОБА формата:
   - обычный JSON { output } или { text } или { message };
   - SSE-стрим (text/event-stream): собрать конкатенацию из строк, начинающихся с "data:",
     игнорируя "[DONE]"; учитывать, что payload может быть JSON { type, content } или строкой.
   Если ответ !ok — вытащи из тела message/hint/error и покажи пользователю.
6. Автоскролл контейнера сообщений вниз после каждого добавления.

=== Б. Базовый n8n-workflow (файл n8n-workflow.json) ===
Собери импортируемый workflow с такой минимальной цепочкой:
"Chat Trigger" → "Ответ в чат" (нода Set), где:
- Chat Trigger: тип @n8n/n8n-nodes-langchain.chatTrigger, mode "webhook", public true,
  webhookId = 9cee9672-ed37-4329-8f81-f20386625bc4, options.allowedOrigins = "*",
  options.responseMode = "lastNode".
- Нода Set «Ответ в чат»: возвращает { output: "..." } — пока простую заглушку,
  например: "Здравствуйте! Я на связи, скоро смогу помочь с выбором подарка."
Контракт: Chat Trigger в режиме lastNode отдаёт в чат поле output последней ноды,
поэтому последней в цепочке обязана быть «Ответ в чат».
Добавь sticky note с TODO-инструкцией (подключить credential, включить Active).
Проверь: корректный JSON, у всех нод уникальные id и согласованные connections.

В конце опиши, как импортировать workflow в n8n и проверить связку curl-командой.
```

## Промпт 3 — Добавить AI-агента в n8n, который ведёт диалог и собирает данные

```text
Продолжаем проект «Морозко». Чат на сайте уже работает, есть базовый workflow
(n8n-workflow.json). Теперь замени ноду-заглушку «Ответ в чат» на полноценного
AI-агента, который ведёт диалог и собирает контакт клиента.

Обнови n8n-workflow.json так, чтобы цепочка была:
"Chat Trigger" → "AI Agent" → "Ответ в чат" (Set, возвращает { output }).
Рядом с агентом — вспомогательные ноды (подключены как ai_languageModel / ai_memory):
- "OpenAI Chat Model": тип @n8n/n8n-nodes-langchain.lmChatOpenAi, model gpt-4o-mini
  (credential оставь placeholder, чтобы пользователь выбрал свой);
- "Simple Memory": тип @n8n/n8n-nodes-langchain.memoryBufferWindow,
  contextWindowLength 10 — чтобы помнить контекст беседы.

Настрой ноду AI Agent:
- promptType: "define", text: "={{ $json.chatInput }}".
- В options.systemMessage задай роль «Морозко» — доброжелательный консультант
  магазина новогодних подарков. Требования к системному промпту:
  * отвечай на языке клиента, поддерживай его весь диалог;
  * пиши кратко, тепло, вежливо, без эмодзи;
  * описывай магазин: работаем с 2014 года, готовые наборы, персональный подбор,
    ручная упаковка и открытка бесплатно, доставка 1–3 дня, корпоративные заказы,
    возврат 30 дней;
  * ассортимент: «Золотая коробка», «Мятный иней», «Фиолетовый бант»,
    «Пряничный пряник», «Полуночная звезда», «Еловый лес»;
  * контакты: телефон 300-10-20, hello@morozko-shop.com;
  * НЕ выдумывай цены, наличие и услуги, которых нет в промпте.

Задача агента по сбору данных (мягко, без допроса, максимум один вопрос за сообщение):
1) для кого подарок (кому и на какой праздник);
2) примерный бюджет;
3) интересы и пожелания;
4) имя клиента;
5) контакт для связи (телефон или email/Telegram).
На основе ответов предложи 2–3 подходящих набора из ассортимента.
Когда собрал минимум имя + контакт — поблагодари и скажи, что менеджер свяжется.

Важные технические требования:
- Последней нодой цепочки остаётся "Ответ в чат" (Set → { output: "={{ $json.output }}" }),
  иначе Chat Trigger ничего не отдаст клиенту.
- Проставь корректные connections: main Chat Trigger→AI Agent→Ответ в чат;
  ai_languageModel от OpenAI Chat Model → AI Agent; ai_memory от Simple Memory → AI Agent.
- Проверь валидность JSON и импортируемость.

Опиши, что изменилось, и как проверить, что агент помнит контекст и собирает данные.
```

## Промпт 4 — Добавить RAG на Qdrant 

```text
Продолжаем проект «Морозко». Сейчас знания о магазине «зашиты» в systemMessage агента.
Нужно вынести их во внешнюю базу знаний и добавить RAG на Qdrant, чтобы агент отвечал
на вопросах из документов (каталог, услуги, FAQ, доставка, возврат).

Цель: при каждом вопросе клиента находить релевантные фрагменты в Qdrant и
подмешивать их в контекст AI Agent как retrieved-контекст (retrieval-augmented generation).

Что сделать:
1. В n8n добавь векторную ноду: Qdrant Vector Store в режиме «retrieve as tool»
   (тип @n8n/n8n-nodes-langchain.vectorStoreQdrant, mode "retrieve-as-tool")
   и подключи её к AI Agent как ai_tool, чтобы агент сам решал, когда искать знания.
   Дай инструменту понятное имя и описание: "search_knowledge_base" —
   "Поиск в базе знаний магазина: ассортимент, цены, доставка, упаковка, возврат, FAQ".
2. Эмбеддинги: подключи OpenAI Embeddings (@n8n/n8n-nodes-langchain.embeddingsOpenAi)
   к векторному стору. Модель и credential — placeholders, пользователь подключит свои.
3. Qdrant: fields для подключения — baseUrl, apiKey, collectionName = "morozko_knowledge".
   Оставь placeholder-значения и пометь их в sticky note как «заполнить».
4. Подготовь отдельный ингест-флоу (опционально, тем же файлом или отдельным
   n8n-workflow-ingest.json): читает документы (Markdown/текст из папки knowledge/),
   нарезает на чанки (разумный размер ~500–1000 символов с перекрытием),
   считает эмбеддинги OpenAI и пишет в коллекцию Qdrant morozko_knowledge.
   Заведи папку knowledge/ и положи туда пример файла morozko.md с фактами о магазине
   (услуги, ассортимент, доставка, упаковка, возврат, контакты).
5. Обнови systemMessage AI Agent: укажи, что факты про магазин нужно брать из
   инструмента search_knowledge_base, а не выдумывать. Если поиск ничего не вернул —
   вежливо предложи связаться с менеджером (300-10-20, hello@morozko-shop.com).
6. Сохрани цепочку валидной: Chat Trigger → AI Agent → «Ответ в чат» остаётся,
   добавляются ai_tool (Qdrant) и ai_embeddings-подключения.

ВАЖНО: этот шаг пока не запускается в проде — подготовь код, конфиг и инструкции
(какие credential и адреса Qdrant подставить, как создать коллекцию, как залить
документы через ингест-флоу). В конце дай чек-лист «что заполнить перед включением».
```

## Промпт 5 — Явная передача клиента менеджеру + диалог менеджера из Telegram

```text
Финальный шаг проекта «Морозко». Чат с AI-агентом уже работает. Нужно реализовать
явную передачу клиента живому менеджеру так, чтобы владелец бота в Telegram мог
сам писать этому клиенту и получать его ответы (двусторонний диалог через Telegram).

Сценарий:
- Пока клиент общается с ботом и не просил менеджера — отвечает AI-агент.
- Как только клиент ЯВНО просит переключить на человека/менеджера (например:
  «позовите менеджера», «хочу с человеком», «соедините с оператором»),
  бот сообщает: «Передаю вас менеджеру, он скоро ответит» — и переключает сессию
  в режим «менеджер ведёт диалог».
- В этом режиме сообщения клиента больше НЕ уходят агенту, а релевантно уходят
  менеджеру в Telegram (текст запроса + имя/контакт клиента + sessionId).
- Менеджер пишет ответ в Telegram — и этот ответ доставляется именно этому клиенту
  в его чат на сайте.

Технически в n8n:
1. Добавь флаг режима по сессии. Простейший вариант — хранить в памяти/статике
   n8n или в отдельной ноде (например, в staticData workflow или во внешнем
   key-value), значение: sessionId → "bot" | "manager". Продумай, где хранить,
   чтобы состояние выживало между запусками, и опиши выбор.
2. Развилка после Chat Trigger (нода IF/Switch):
   - если режим "manager" — направить сообщение в Telegram (нода Telegram Send,
     chatId менеджера) и вернуть клиенту { output: "" } (или короткое «Отправил
     менеджеру»), НЕ вызывая агента;
   - иначе — отдать AI Agent, как раньше.
3. Детект явного запроса менеджера. Надёжнее — поручить это агенту: в systemMessage
   опиши, что при явной просьбе перевести на человека агент обязан вызвать
   инструмент handoff_to_manager и кратко сообщить клиенту, что менеджер подключится.
   Реализуй handoff_to_manager как ai_tool (Telegram-уведомление менеджеру
   с текстом клиента) и/или как другую ноду, которая переключает режим сессии на
   "manager". Можно дополнительно подстраховаться простым ключевыми словами.
4. Обратный канал (менеджер → клиент): добавь Telegram Trigger, который ловит
   сообщения менеджера, определяет нужный sessionId (ответ на уведомление/reply_to,
   либо указанный менеджером sessionId) и отправляет текст клиенту на сайт.
   Для доставки используй механизм, поддерживаемый Chat Trigger (например, вернуть
   сообщение в сессию через соответствующий webhook/ноду; если прямой отправки нет —
   опиши и реализуй буферизацию: ответ менеджера сохраняется и отдаётся клиенту
   при следующем опросе/запросе). Чётко опиши, как именно это работает.
5. Telegram-ноды оставь с placeholder-credential и пометь в sticky note:
   «подключить Telegram bot token, указать chatId менеджера, включить ноды».
   Telegram Trigger — отдельная ветка, тоже помечена disabled до настройки.

Требования:
- Не сломай существующую цепочку: Chat Trigger → ... → «Ответ в чат» ({ output }).
- Корректный, импортируемый JSON; согласованные connections и уникальные id.
- Учти, что менеджер может вести несколько клиентов — не перепутай сессии.
- Гарантируй, что после переключения AI-агент НЕ отвечает вместо менеджера.

В конце опиши: где хранится состояние сессий, как менеджер понимает, какому клиенту
он пишет, и полный чек-лист настройки Telegram для запуска.
```
